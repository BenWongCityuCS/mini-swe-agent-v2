    Extensions: skills, subagents, MCP, and mounted prompts

    This fork adds an optional extension layer inspired by ZCode. Everything is opt-in and disabled by default, so a stock config behaves exactly like upstream mini-swe-agent v2.

    All settings live under agent and can be layered on top of mini.yaml:

    mini -c mini.yaml -c extensions.yaml --task "..."

    Extensions require a tool-call model (--model-class litellm, the default for OpenAI-compatible endpoints). Text-action models do not expose tool schemas and will raise a clear error if extensions are enabled.

    Skills

    Skills are Markdown files with YAML frontmatter. The index (name, description, path) is added to the system prompt; the full body is loaded on demand through the Skill tool, so unused skills cost almost no context.

    skills/
  pdf/SKILL.md
  quick.md

    ---
name: pdf-tools
description: Work with PDF files
when_to_use: when a task involves generating or reading a PDF
aliases: [pdf]
---
Use the pdf CLI. Relative paths are resolved against ${SKILL_DIR}.

    agent:
  skills:
    enabled: true
    dirs: ["./skills", "~/.mini-swe-agent/skills"]
    max_description_chars: 250
    max_index_chars: 20000
    max_bytes: 100000

    Discovery rules:

    • <dir>/**/SKILL.md is a directory skill; its base directory is the parent.
    • <dir>/*.md is a single-file skill; its base directory is <dir>.
    • Later directories override earlier ones with the same name.
    • ${SKILL_DIR}, ${ZCODE_SKILL_DIR}, ${SKILL_BASE_DIR}, and ${WORKSPACE} are expanded when the skill is loaded.

    Subagents

    A Task tool delegates work to a nested agent with its own message history. The subagent shares the environment (same container, same working directory), runs with a filtered tool set, and returns only its final report to the coordinator.

    Built-in profiles:

    Profile Purpose Default tools
    general-purpose Multi-step research or side work all tools
    explore Read-only fan-out search Read, Grep, Glob

    Custom profiles are Markdown files with frontmatter:

    ---
name: reviewer
description: Reviews a diff and reports risks
tools: Bash, Read, Grep, Glob
inject_prompts: true
max_steps: 40
---
You are a code review subagent. ...

    agent:
  subagents:
    enabled: true
    profile_dirs: ["./agents", "~/.mini-swe-agent/agents"]
    max_depth: 1
    default_type: general-purpose
    inherit_skills: true
    step_limit: 0
    max_result_chars: 20000

    tools accepts "*", exact names (Read, Skill, mcp__fs__read_file), or glob patterns (mcp__fs__*). An empty list gives the subagent only bash. Subagents never receive the Task tool unless max_depth allows it.

    Mounted prompts are inherited when inject_prompts: true; the skills index is inherited when inherit_skills is true and the profile includes Skill.

    Subagents submit their report with a heredoc so the coordinator receives text:

    cat <<'MSWEA_SUBMIT'
COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT
Answer: ...
Files: /path/to/file.py:123
MSWEA_SUBMIT

    MCP servers

    MCP tools are exposed as mcp__<server>__<tool> with the server's JSON schema passed through unchanged. Servers are started once per agent and called from a background event loop; HTTP/SSE servers are supported as well as stdio.

    {
  "mcpServers": {
    "fs": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
    },
    "docs": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": {"Authorization": "Bearer ..."}
    }
  }
}

    agent:
  mcp:
    enabled: true
    config_file: "./mcp.json"
    timeout_seconds: 60
    max_output_chars: 50000
    tool_prefix: mcp
    required: false

    Servers can also be declared inline under agent.mcp.servers. A server that fails to start is skipped with a warning (visible in the trajectory under extensions.mcp_diagnostics); set required: true to fail fast instead. Legacy Claude/OpenCode fields are normalized: environment → env, http_headers → headers, enable → enabled, type: "remote" → "http".

    MCP tool output is rendered as text; images become [image <mime>] placeholders, and the total output is capped by max_output_chars.

    Mounted prompts

    Mount any Markdown/text files into the system prompt without editing the YAML templates. This is the equivalent of AGENTS.md injection.

    agent:
  prompts:
    files: ["AGENTS.md", "docs/agent-rules.md"]
    dirs: ["prompts"]
    required: false
    tag: mounted_instructions
    header: Mounted instructions
    • Relative paths are resolved against agent.workspace (default: the environment cwd).
    • files may contain globs; dirs loads *.md and *.txt recursively in sorted order. Duplicates are removed.
    • ${WORKSPACE} is expanded in the mounted text.
    • Content is appended verbatim (no Jinja rendering), wrapped in <mounted_instructions>...</mounted_instructions>.

    Read-only tools

    Read, Grep, and Glob are available to subagent profiles without shelling out. To give them to the main agent too:

    agent:
  tools:
    read_only: true

    Security notes

    • MCP servers execute arbitrary local commands (stdio) or receive your credentials (http/sse headers). Treat mcp.json as code.
    • Subagents share the same environment as the coordinator. Tool filtering is a prompt-safety feature, not a sandbox: bash can still do anything the container user can do.
    • Mounted prompts are trusted input. Do not point them at files controlled by an untrusted party.

    Trajectory metadata

    Each run records the active extension set:

    "extensions": {
  "tools": ["Skill", "Task", "mcp__fs__read_file"],
  "skills": ["pdf-tools"],
  "subagent_profiles": ["explore", "general-purpose"],
  "mcp_servers": ["fs"],
  "mcp_diagnostics": [],
  "mounted_prompts": ["/workspace/AGENTS.md"]
}
